# dsh-workday-schedule · 工作日定时任务

给 DSH 的自动化任务加上**节假日 / 调休**规则：只在设定的工作日执行，自动跳过法定节假日，调休补班日照常跑。

## 为什么需要它

内置的 `schedule_create` 只认 `after / at / every / daily / weekly / cron`，cron 的星期范围 `1-5` 既躲不开**法定节假日**，也接不住**调休补班的周六周日**。结果是国庆节照样发日报、调休上班那天反而没有任务。

本插件把「哪一天算工作日」这件事从日历规则里解耦出来：

- 法定节假日 → 跳过
- 调休补班日（周末上班）→ 照常执行
- 普通周末 → 跳过

## 页面：接管原生「自动化任务」页

插件自带客户端页面，注册在 `main` 槽位的 `schedules` 键上，**替换**原生自动化任务页。它的「重复」下拉比原生多两项：

| 重复选项 | 底层记录 | 行为 |
| --- | --- | --- |
| 仅一次 | `at` | 原生语义 |
| 每天 | `daily` | 原生语义 |
| **工作日** | `weekly` + weekdays `[1,2,3,4,5]` | 跳过法定节假日，调休上班日照跑 |
| **休息日** | `weekly` + weekdays `[6,7]` | 周末与法定节假日执行，遇调休上班日停跑 |
| 每周 | `weekly` + 自选星期 | 原生语义 |
| 自定义 | `cron` | 原生语义 |

节假日的正确性由 Host 侧引擎保证（见下节）。页面与引擎之间**没有私有接口**，契约是记录标题末尾的后缀：

- ` · 工作日` → 该记录按工作日规则管理
- ` · 休息日` → 该记录按休息日规则管理

因此任何来源创建的记录（页面、工具、智能体）行为一致；没有标记的记录引擎完全不碰。

## 设计：用原生递归记录承载，用暂停/补排纠正节假日

插件不自己发提醒、不做投递，而是把每个任务映射成内置 Schedule 里的**递归提醒**，让自动化任务页显示一条真实的重复规则（如「每周一至周五 13:30」），而不是「仅一次」。原生只能表达日历规则，插件再用两种手段把它校正成节假日规则：

- **抑制（暂停）**：下一次原生执行若落在应排除的日子（工作日任务遇到法定节假日、休息日任务遇到调休上班日），插件提前把提醒**暂停**，过完再恢复。因为是在执行点之前暂停，被排除的日子**根本不会唤醒模型**。
- **补排（一次性）**：规则要求、但基础日历表达不了的日子（调休上班的周末、休息日任务遇到假日里的工作日），单独挂一条一次性提醒，滚动维护未来 60 天。

因此：

- 官方投递链路、执行历史、重启恢复全部照旧生效；
- 任务在原生页面显示为**真实的重复规则**，「下次运行」永远准确，日期/时间字段不再空白；
- 用户在原生页面**手动暂停** → 插件把任务一起停用，不会偷偷恢复；
- 用户在原生页面**删除** → 插件视为停用，不会偷偷加回来；
- 递归提醒创建失败时降级为「每次物化成一次性记录」，任务不会停摆（代价是页面显示「仅一次」）。

## 节假日数据：后台静默更新

三层数据，新的覆盖旧的：

1. 内置快照 `src/seed-holidays.json`（随包分发，离线可用；当前覆盖 `2004-01-01 .. 2027-10-09`）
2. 运行时缓存 `~/.dsh/workday-schedule/holiday-cache.json`（后台更新写入）
3. 全失败时保持上一份，绝不打断任务

启动后约 20 秒尝试一次，之后按 `updateIntervalHours`（默认 12 小时）静默刷新，数据源 `chinese-days`（npmmirror → unpkg 自动降级）。**更新过程对用户完全不可见**：没有提示、没有设置项、失败也不告警。用户只需要在自动化任务页看到「下一次什么时候跑」。

国务院一般 11 月发布次年安排，上游 `chinese-days` 随后跟进，插件会自动跟上。数据没覆盖到的日期按 `fallbackWhenUnknown` 处理（默认 `run`，宁可多跑一次也不静默漏跑）。

> **维护提示**：内置快照必须**领先于「今天」**，否则断网/源不可用时等于没有节假日数据。
> 发布前跑一次 `node scripts/build-seed.mjs` 即可（脚本会先解析上游 `latest` 版本再拉数据，
> 不再写死版本号）。`test/holiday-seed.test.mjs` 里有新鲜度断言守着这一点。

## 配置项（插件设置页自动生成）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `weekdays` | `[1,2,3,4,5]` | 新建任务默认运行星期（1=周一 … 7=周日） |
| `skipHolidays` | `true` | 跳过中国法定节假日 |
| `runOnMakeupWorkdays` | `true` | 调休补班日照常执行 |
| `fallbackWhenUnknown` | `run` | 数据未覆盖时的取舍：`run` / `skip` |
| `timeZone` | `Asia/Shanghai` | 判定工作日与计算执行时刻所用时区 |
| `autoUpdate` | `true` | 后台静默更新节假日数据 |
| `updateIntervalHours` | `12` | 后台更新间隔（小时） |

## 工具

| 工具 | 作用 |
| --- | --- |
| `workday_task_create` | 新建任务（标题、prompt、时间、星期、`day_kind`、节假日策略；可用 `session_id` 绑到其它会话） |
| `workday_task_list` | 列出任务、规则、下一次执行时间与数据覆盖范围 |
| `workday_task_update` | 改标题/内容/时间/星期/`day_kind`/节假日策略，或暂停 |
| `workday_task_delete` | 删除任务并撤掉已排的提醒 |
| `workday_check` | 查某天/某区间是不是工作日，说明是节假日还是调休补班 |

## 已知边界

- 只处理中国大陆法定节假日与调休；其他地区可替换 `src/holiday.js` 的数据源。
- 内置快照覆盖 `2004-01-01 .. 2027-10-09`，之后依赖后台更新补齐；后台更新覆盖到更新版本时会自动抬高上限。
- 用户在原生页面手动改动的提醒时间，下一次对账会按任务规则纠正回来。
- 「暂停」是靠原生状态实现的：节假日期间任务在页面上显示为**已暂停**，这是预期行为，不是故障。
- 基础递归规则只覆盖日历（如周一至周五、周末）；节假日排除与调休补排由插件在每次对账时维护，需要插件处于运行状态。
