# dsh-workday-schedule · 工作日定时任务

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的自动化任务加上**节假日与调休**规则。

一句话：**让任务在「真正上班的日子」跑，而不是在「星期一到星期五」跑。**

## 为什么需要它

### 中国特色调休，让「按周排期」这件事失效

中国的放假安排不是「周六周日固定休息」这么简单：法定节假日会**把工作日变成休息日**（春节连休七天），调休又会**把周末变成工作日**（某个周六照常上班）。一年下来，实际休息日和日历上的周末能差出十几天。

这让「日报、周报、对账、巡检、打卡提醒」这类**跟着工作日走**的任务特别难做：

| 想要的 | 用 cron / 每周一到周五 | 实际结果 |
| --- | --- | --- |
| 春节假期别发日报 | 10-01 到 10-07 照样触发 | 假期里刷屏，或者让模型自己判断「今天该不该发」 |
| 调休的那个周六要发 | 周六不在 `1-5` 里 | 该上班却漏了一条 |
| 长假后补一次汇总 | 只能等到下周一 | 隔了八九天，数据早断了 |

而「让模型每次自己判断今天上不上班」也不可靠：判断依据要么靠联网查国务院通知（网络受限时直接失败），要么退回「周一到周五」兜底 —— 节假日照样误跑。

### 这个插件做什么

把「哪一天算工作日」从日历规则里解耦出来，交给插件按真实节假日数据判断：

- 法定节假日 → 跳过
- 调休补班日（周末上班）→ 照常执行
- 普通周末 → 跳过

于是排期可以按**工作节奏**来写，而不是按星期：

- 「每个工作日早上发日报」—— 假期自动停，调休自动补
- 「每个休息日第一天」—— 一段工作结束后触发，用来补录、汇总、对账
- 「假期最后一天」—— 提前把下周要用的东西准备好
- 「节后第 2、3 个工作日」—— 前一天的遗留问题再催一次

任务内容仍然是你的，插件只负责「什么时候触发」这件事。

### 可选：执行后把结果写进面板

每个任务有一个「**执行后汇报结果**」开关（默认关闭）。打开后，投递内容末尾会追加一段要求：

```
【完成后请记录结果】
本次执行末尾调用一次 workday_task_report 工具：
- id：本任务的 id
- summary：一句话说明做了什么、结果如何（不超过 60 字）
- status：ok / partial / failed / skipped
不要在对话里复述过程，也不要贴大段日志。
```

结果写进任务的执行记录，**面板上每条执行都会多一行结果**（状态徽章 + 一句话摘要），而不是只在会话里说一遍。

关掉这个开关，投递内容就是你写的原文，一个字都不多。

这个开关只在插件托管的任务上出现（工作日 / 休息日 / 节假日第一天 / 组合规则）；仅一次、每天、每周、自定义这类走宿主原生规则的任务不显示它，因为那里插件不参与投递内容。

### 技术上的原因

内置的 `schedule_create` 只认 `after / at / every / daily / weekly / cron` 这几种**纯日历**规则：cron 的星期范围 `1-5` 既躲不开法定节假日，也接不住调休补班的周六周日。它没有、也不可能有「今天算不算工作日」这个概念 —— 那需要一份每年更新的国务院放假安排。

本插件补的就是这块：把节假日数据、调休判断和「第几个工作日」这类序号规则做进排期层，再映射回原生 Schedule 的递归记录。

## 能力

### 重复方式

页面上的「重复方式」下拉提供：

| 选项 | 含义 |
| --- | --- |
| 仅一次 / 每天 / 每周 / 自定义 | 原生语义，不做节假日处理 |
| **工作日** | 周一至周五，自动跳过法定节假日，调休上班日照跑 |
| **休息日** | 周末与法定节假日执行，调休上班日不跑 |
| **节假日第一天** | 只在休息段的第一天执行（连休其余日子不跑） |
| **组合规则** | 按「连续段 / 本周 / 本月」数第几个工作日或休息日 |

### 组合规则

一条规则是若干**选择器**的并集。每个选择器回答三件事：

```
{ dayType: 'workday' | 'restday',   // 哪类日子
  anchor:  'stretch' | 'week' | 'month',  // 按什么数
  ordinals: [2, 3],                 // 第几个，负数 = 倒数（-1 = 最后一个）
  every: 1 }                        // 每 N 个周期一次（仅本周内支持）
```

能表达的例子：

| 需求 | 规则 |
| --- | --- |
| 假期最后一天 | `休息日 + 连续段 + -1` |
| 节后第 2、3 个工作日 | `工作日 + 连续段 + 2,3` |
| 每两个月的最后一次上班 | `工作日 + 本月 + -1` |
| 上面两种都要 | 两个选择器并列（并集） |

> **注意语义**：`连续段 + 第 N 个` 是「一段连续工作日里的第 N 天」。在普通一周里，那段就是周一到周五，所以「第 2 个工作日」等于周二 —— 它同时匹配「每周二三」和「长假后第 2 天」。若你只想表达「长假之后」，目前用 `休息日 + 连续段 + 1` 配合任务内容里的幂等逻辑更稳妥。

页面里配规则时会**实时预览**接下来会在哪几天触发；智能体侧可以用 `workday_check` 传 `rule` 参数拿到同样的预览。

### 独立页面

插件自带一个「工作日任务」页面（侧边栏入口，排在原生「自动化」之后），包含：

- **任务列表**：置顶、默认展开，每条带与月历一致的颜色点
- **统计**：本月触发次数、本月已执行、下次执行倒计时、窗口内跳过/补排
- **月历**：四色区分工作日 / 休息日 / 法定节假日 / 调休上班，节假日在格子里写出节日名，调休上班标「班」；点某天展开当天触发详情
- **执行记录**：来自宿主真实投递历史（计划时刻 vs 实际投递时刻），显示准时/延迟

原生「自动化」页面完全不动，两个页面并存且数据同源。

## 设计：用原生递归记录承载，用暂停/补排纠正节假日

插件不自己发提醒、不做投递，而是把每个任务映射成内置 Schedule 里的**递归提醒**，让自动化任务页显示真实重复规则（如「每周一至周五 13:30」），而不是「仅一次」。原生只能表达日历规则，插件再用两种手段校正：

- **抑制（暂停）**：下一次原生执行若落在应排除的日子，插件提前把提醒**暂停**，过完再恢复。因为是在执行点之前暂停，被排除的日子**根本不会唤醒模型**。
- **补排（一次性）**：规则要求、但基础日历表达不了的日子（调休上班的周末、休息日任务遇到假日里的工作日），单独挂一条一次性提醒，滚动维护未来 60 天。

因此：

- 官方投递链路、执行历史、重启恢复全部照旧生效
- 任务在原生页面显示为真实的重复规则，「下次运行」永远准确
- 用户在原生页面**手动暂停** → 插件把任务一起停用，不会偷偷恢复
- 用户在原生页面**删除** → 插件视为停用，不会偷偷加回来
- 递归提醒创建失败时降级为「每次物化成一次性记录」，任务不会停摆

## 节假日数据：后台静默更新

三层数据，新的覆盖旧的：

1. 内置快照 `src/seed-holidays.json`（随包分发，离线可用；当前覆盖 `2004-01-01 .. 2027-10-09`）
2. 运行时缓存 `~/.dsh/workday-schedule/holiday-cache.json`（后台更新写入）
3. 全失败时保持上一份，绝不打断任务

启动后约 20 秒尝试一次，之后按 `updateIntervalHours`（默认 12 小时）静默刷新，数据源 `chinese-days`（npmmirror → unpkg 自动降级）。**更新过程对用户完全不可见**：没有提示、没有设置项、失败也不告警。

国务院一般 11 月发布次年安排，上游随后跟进。数据没覆盖到的日期按 `fallbackWhenUnknown` 处理（默认 `run`，宁可多跑一次也不静默漏跑）。

> **维护提示**：内置快照必须**领先于「今天」**，否则断网时等于没有节假日数据。发布前跑一次 `npm run build:seed`（脚本会先解析上游 `latest` 版本再拉数据）。`test/holiday-seed.test.mjs` 里有新鲜度断言守着这一点。

## 配置项（插件设置页自动生成）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `weekdays` | `[1,2,3,4,5]` | 新建任务默认运行星期 |
| `skipHolidays` | `true` | 跳过中国法定节假日 |
| `runOnMakeupWorkdays` | `true` | 调休补班日照常执行 |
| `fallbackWhenUnknown` | `run` | 数据未覆盖时的取舍：`run` / `skip` |
| `timeZone` | `Asia/Shanghai` | 判定工作日与计算执行时刻所用时区 |
| `autoUpdate` | `true` | 后台静默更新节假日数据 |
| `updateIntervalHours` | `12` | 后台更新间隔（小时） |

## 工具

| 工具 | 作用 |
| --- | --- |
| `workday_task_create` | 新建任务；支持 `day_kind`、`rule`（组合规则）、`session_id`（绑到其它会话） |
| `workday_task_update` | 改标题/内容/时间/规则/启停 |
| `workday_task_delete` | 删除任务并撤掉已排的提醒 |
| `workday_task_list` | 列出任务、规则、下次执行与数据覆盖范围 |
| `workday_check` | 查某天/某区间是不是工作日；传 `rule` 则预览规则的实际触发日 |
| `workday_task_report` | 记录一次执行的结果（status + 一句话摘要），写进面板的执行记录 |

## 已知边界

- 只处理中国大陆法定节假日与调休；其他地区可替换 `src/holiday.js` 的数据源。
- 内置快照覆盖 `2004-01-01 .. 2027-10-09`，之后依赖后台更新补齐。
- 「暂停」是靠原生状态实现的：节假日期间任务在页面上显示为**已暂停**，这是预期行为。
- 基础递归规则只覆盖日历；节假日排除与调休补排由插件每次对账维护，需要插件处于运行状态。
- 组合规则的「连续段」语义见上文注意点，暂不支持「仅前置休息段 ≥ N 天」这类限定。
