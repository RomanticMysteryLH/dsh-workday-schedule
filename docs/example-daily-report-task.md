# 示例：把「休息日第一天」用在一个填报任务上

这是一份**参考范例**，不是插件的一部分。它演示怎么把工作日规则和任务内容结合，让模型不必自己判断今天该不该上班。

示例任务：每个工作段结束后，把刚过去的这段工作日批量补录到某个系统里。

## 为什么规则要交给插件判断

如果让 prompt 自己判断「今天是不是该干活」，它会依赖联网查节假日、或者干脆用「周一至周五」兜底 —— 前者经常查不到，后者在法定节假日会误跑。把判断放在**排期层**，模型被唤醒就一定是该干活的那天。

## 规则设置

| 字段 | 值 |
| --- | --- |
| 重复方式 | 休息日 → 第一个（或组合规则：`休息日 + 连续段 + 1`） |
| 执行时间 | 10:00 |
| 执行位置 | 执行该任务的那个会话 |

## 任务内容（prompt）

```text
为 <你的账号> 填报 <系统名称> 日报。使用 <对应技能> 执行，本消息只提供「填什么」，具体操作方式全部按技能来。

【触发时机：不需要判断】
本任务由工作日历保证：只在「休息日的第一天」触发 —— 也就是一段连续工作日结束后的那个早晨。
连休的其余日子、调休上班日、普通工作日都不会触发。
所以被触发时，直接执行填写即可，不需要再判断今天是星期几、是不是节假日、是不是第一天。

【要填哪几天：紧邻的前一段连续工作日】
从昨天开始往前回溯，取「截止昨天、连续不断的工作日」这一段。
- 用 workday_check 查「昨天往前 20 天」的区间，从结果里取出这段连续的工作日。
- 通常就是上一个周一至周五（5 天）。
- 长假前只填假期开始前的那几天（例如国庆前只填 3 天）。
- 调休上班的周六周日算工作日，会自然包含进来。
这一步的日期必须按 workday_check 的真实结果算，不要凭印象。

【每天填什么】
……（按你的系统填写规则）

【幂等】
已经填过的天跳过，不要重复写、也不要覆盖已有记录。

【完成后】
重新拉一次数据，确认真实落库后再向用户报告；某天无法完成要说明原因，不要静默跳过。
```

## 要点

- **不要**在 prompt 里写「如果是节假日就不发」—— 那是排期层的职责，写进去反而会让模型多一层不确定判断。
- 日期范围一律用 `workday_check` 查，不要凭印象算，否则调休一定会算错。
- 任务内容里明确「幂等」，因为规则可能因为手工补排而多触发一次。
